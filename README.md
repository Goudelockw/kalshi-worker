# kalshi-worker

Ingests Kalshi market history into Neon Postgres (schema from `001_kalshi_schema.sql` + `002_fixed_point_types.sql`).

## Commands
| command | what | how it runs on Railway |
|---|---|---|
| `backfill` | daily candles for settled markets that have none yet; resumable | one-off (`railway run python -m kalshi_worker backfill`) |
| `sync` | open events + markets, hourly candles, watchlist trades + 1-min candles, then the stale sweep (`--max N`, default 20000) | cron service, `0 * * * *` |
| `reconcile` | complete candles for recently settled markets, then the stale sweep (`--max N`) | cron service, `15 4 * * *` |
| `sweep` | only the stale sweep: re-fetch non-finalized/settled markets not in the open-events pull via `/markets?tickers=`, least recently updated first, up to `--max N` (default 20000) | one-off catch-up |
| `transcripts` | discover new Motley Fool transcript URLs for companies with earnings-mention markets from the monthly sitemaps (`--discover-months N`, default 2; symbols never backfilled get 36 months once, marked by `transcripts_backfill:<SYMBOL>` in `sync_state`; `--backfill-symbol SYM` clears the marker so this run re-scans SYM), then fetch + parse pending ones into `transcripts` / `transcript_segments`; `--limit N` for testing; `--reparse` re-runs the parser on stored HTML for transcripts whose segments hold under 70% of their words or whose page date was never parsed; `sql/` holds the schema additions and the `v_transcript_mentions` base-rate view | on demand (`railway run python -m kalshi_worker transcripts`) |
| `fortune` | Fortune.com (Quartr) transcripts as a second source (`source='fortune'`): finds `company_map.fortune_slug` for tracked companies without one (name-based candidates checked against the page's ticker; re-checked every 30 days), then stores new calls from each company's earnings reports as `transcripts` + speaker-merged `transcript_segments`; calls whose transcript isn't posted yet stay `pending` in `transcript_sources` and are retried; `--symbol SYM`, `--limit N` (report pages); 1 request/second | runs at the end of `transcripts`, or on demand |
| `equibles` | Equibles API transcripts only for calls no other source has: works `kalshi.v_transcript_gaps` (label-audit `no_transcript` events and 2 years of earnings releases with no transcript within 3 days; `sql/009_equibles.sql`), newest first, each gap at most once per 7 days (`kalshi.equibles_attempts`); settled Kalshi calls first, then newest; per symbol one `/investor-events` listing, the `EarningsCall` with a transcript within 5 days of the target, then its `/speakers` pages (50 turns each) stored as `source='equibles'`; at most 90 requests per run (every request counts), stops cleanly on the budget or 429 without storing a partial call; `--limit N` gaps; needs `EQUIBLES_API_KEY` | runs at the end of `transcripts` after `fortune`, or on demand |
| `filings` | fills `company_map` for every earnings-mention symbol (`ticker` from `kalshi_worker/tickers.py` aliases, e.g. ADOBE→ADBE, ARITZIA→ATZ; SEC CIK looked up by ticker, null for TSX-only; `sql/010_company_map_ticker.sql`); 8-K earnings press releases (Item 2.02, Exhibit 99.1) and foreign filers' 6-K results releases (Exhibit 99.1 announcing results in its first 1,500 characters; stored with form `6-K`, no items) from SEC EDGAR for companies with earnings-mention markets into `filings`; symbols never backfilled get three years once, older submissions pages included (`filings_backfill:<SYMBOL>` in `sync_state`; `--backfill-symbol SYM` re-runs it); plus corporate-event 8-K / 8-K/As (items 1.01, 1.02, 2.01, 2.05, 2.06, 5.02) into `corporate_events` and SIC codes into `company_map`; `--days N` (default 3, use 1100 for the backfill); `--reparse` splits stored rows into `body_text` / `boilerplate_text`; needs `SEC_CONTACT_EMAIL` | cron service, daily, or on demand |
| `mentions-backfill` | one-off: every `KXEARNINGSMENTION*` series from `/series`, then per series its events, archived markets (`/historical/markets`) and settled live-tier markets, upserted; finished series marked `mentions_backfill:<series>` in `sync_state` and skipped on rerun; then `precall` for settled markets without hourly windows and the word-count refresh | `railway run python -m kalshi_worker mentions-backfill` |
| `precall` | hourly candles for each settled earnings-mention call over [anchor - 48h, max(anchor + 3h, close + 1h)], anchored on `mv_call_times.call_start_est` (else the event's earliest market close_time); `--refetch-missing` re-fetches events with incomplete prices in `mv_precall_prices` (clears their `precall_done` markers, then refreshes the views); historical-tier markets one per call, live ones batched per event; done markets marked `precall_done:<ticker>` in `sync_state` (or skipped with >= 40 hourly candles in the window); newest events first, `--limit N` events. `reconcile` runs it for markets settled in the last 3 days, and `sync` fetches the last 3h of hourly candles for open earnings-mention markets whose call is within 2 days (New York) | one-off backfill, then automatic |
| `reactions` | 1-minute candles from 3h before each 8-K earnings release to 5 min after close for the filer's mention markets closing within 36h; feeds `v_release_reaction`; `--days N` (default 3, 90 for the backfill) | cron service, daily, or on demand |
| `news` | pre-call Google News volume from the Serper API (`sql/012_news.sql`): per earnings-mention market, counted articles for `"<company>" "<word>"` (`yes_sub_title` without "(N+ times)"; "A / B" becomes `("A" OR "B")`; company = `company_map.name` minus Inc / Corp / Co / Holdings / Ltd / plc / Group, or an override in `news.NAME_OVERRIDES`) and, once per event, for the company alone (stored under `'__company__' \|\| event_ticker`). No leakage past the call: the query window is [call day - 14, call day - 1] in New York from `mv_call_times.call_start_est` (events without one are skipped), and no article counts until `news-dates` has read its publish time from the page: every returned article goes to `news_articles` as `counted = false`, `reject_reason = 'unverified'` (Serper's own date is kept in `date_raw` / `published_at` for reference only), and the run ends by running `news-dates` on the articles it stored; totals go to `news_counts` (`dates_verified` once all of a market's and its baseline's articles are checked); a Serper error is stored in `news_counts.error` and retried next run, and 401/403/429 or no credits stops the run. Default: calls starting in 3h-3 days; `--backfill`: settled markets without a `news_counts` row (or with an errored one), newest calls first. 5 requests/s, at most 2,000 per run (logs what is left). Every run ends with the self-check `select count(*) from kalshi.news_articles where counted and (exact_published_at is null or exact_published_at >= cutoff)` (the run fails if it is above 0) and a summary line; needs `SERPER_API_KEY` | cron service `news`, `30 11 * * *`; backfill by hand (`nohup python -m kalshi_worker news --backfill > /tmp/news.log 2>&1 &`, about 4 runs) |
| `news-dates` | exact publish times for news articles (`sql/013_news_exact_dates.sql`), because Serper's dates are mostly relative ("10 months ago", from the fetch) and Google re-dates stale pages: for each `news_articles` row not yet checked (or reset to `unverified` by a `news` re-fetch), newest `call_start` first, GETs the page (10s timeout, redirects, browser User-Agent; 5 requests/s overall, 1/s per domain) and takes the first timezone-aware time from JSON-LD `datePublished` (`@graph` too), `<meta property="article:published_time">`, `<meta name="pubdate\|publishdate\|date\|DC.date.issued\|parsely-pub-date\|sailthru.date">`, `<meta itemprop="datePublished">`, then the first `<time datetime>` in `<article>` (modified dates never; a date alone = 23:59 NY). Stores `exact_published_at`, `date_source` (or `none`), `http_status`, `date_checked_at`, then `counted` = exact time before `cutoff`, not before `news_counts.window_start`, not a stale re-date and not a recap title; otherwise `no_exact_date`, `after_cutoff_exact`, `stale_redate` (the exact time is over 30 days before the earliest time Serper's date allows, e.g. "4 days ago" -> 5 days before the fetch), `before_window_exact` or `recap_title`. Once every article of a market and of its event's `__company__` baseline is checked, recomputes `news_counts` counts from `counted` and sets `dates_verified`. `--limit N` rows; ends with the same self-check as `news` and a summary (checked, exact dates by source, counted, rejected by reason). Failed requests are marked checked with `http_status` 429 / 5xx / null; clear their `date_checked_at` to retry | runs at the end of each `news` run; backfill by hand (`nohup python -m kalshi_worker news-dates > /tmp/nd.log 2>&1 &`) |
| `worker` | always-on; takes an order-book snapshot for watchlist series every N min | default service |

`transcripts` and `filings` both end by logging the tracked symbols with no transcripts / filings and running the refresh chain (`sync` does the same after its stale sweep, `precall --refetch-missing` after its re-fetch). The chain (`db.refresh_word_counts`, each step in its own transaction with a 10-minute statement timeout) runs `kalshi.resolve_speaker_roles()`, then refreshes, in order: `mv_word_counts`, `mv_call_stats`, `mv_call_analysts`, `mv_call_analyst_stats`, `mv_analyst_features`, `mv_call_features`, `mv_call_execs`, `mv_earnings_dates`, `mv_exec_features`, `mv_segment_tsv`, `mv_word_corpus_hits`, `mv_word_corpus`, `mv_word_context` (`sql/011_mv_word_context.sql`), `mv_call_times`, `mv_precall_prices`, `mv_word_features`, `mv_model_input` (all `CONCURRENTLY` except `mv_call_times` and `mv_precall_prices`). A failed step is logged and the chain goes on; it ends with `refresh: N of 18 steps failed: <names>`. `transcripts`, `filings` and `sync` only log failures; `precall --refetch-missing` fails its run. `sql/008_source_coverage.sql` adds `v_source_coverage`: one row per earnings-mention symbol with transcript / filing counts, latest call / filing, CIK and the two backfill flags.

Call start times (`kalshi.v_call_times_base` → `v_call_times` → `mv_call_times.call_start_est`, `call_start_source`): the time in the release text (`release_text`), else the first 1-minute lock after the release minus 20 min (`first_lock_minus_20m`). With neither: a `kalshi.call_time_overrides` row (`manual_override`), else `kalshi.event_date()` + the company's usual call time (median New York time of day of its earlier `release_text` / `first_lock_minus_20m` calls; `event_date_plus_company_time`), else the event date + 08:30 ET if the release came before that day's 09:30 ET open, otherwise 17:00 ET (`event_date_plus_default_time`), else the old busiest-hourly-lock guess (`hourly_lock_peak_minus_90m_lowconf`). The event-date rules are used only when the start falls before the event's first market close and within 3 days of it. An override wins for every event (`sql/013_call_time_fallback.sql`).

## Railway setup
1. Create the repo on GitHub, push this directory.
2. In the `kalshi-data` project: **+ New → GitHub Repo** → this repo. Name the service `worker`. Uses the Dockerfile CMD.
3. Add two more services from the same repo: `sync` (start command `python -m kalshi_worker sync`, cron `0 * * * *`) and `reconcile` (start command `python -m kalshi_worker reconcile`, cron `15 4 * * *`).
4. Shared variables: `DATABASE_URL` (Neon pooled string with `?sslmode=require`), `SERPER_API_KEY` (for `news`), optionally `KALSHI_RPS`, `SNAPSHOT_INTERVAL_MIN`.
5. Kick off the backfill once from the `worker` service's shell or `railway run`.

## Local
```
cp .env.example .env   # fill DATABASE_URL
pip install -r requirements.txt
python -m kalshi_worker sync
```

## Monitoring
`SELECT job, max(finished_at), bool_and(ok) FROM kalshi.ingest_runs WHERE started_at > now()-interval '1 day' GROUP BY 1;`
